# Постановка бизнес-задачи

## Актуальность
В настоящее время для идентификации пользователей в приложениях часто используются биометрические данные, в частности биометрия лица человека. Для улучшения точности идентификации, перед сравнением с эталоном лицо может проходить процесс нормализации (выравнивания). Для этого необходимо решать задачу определения ключевых точек лица на изображении.

## Данные
Данные представляют собой изображения лиц человека с 14 размеченными ключевыми точками:
- 1-2: левая бровь
- 3-4: правая бровь
- 5-7: левый глаз
- 8-10: правый глаз
- 11: нос
- 12-14: рот

Новые данные планируется получать регулярно, семплируя кадры, полученные во время верификации в приложении, и размечать с помощью асессоров. Также можно рассмотреть генерацию синтетических данных с последующей разметкой асессорами (исключаются вопросы приватности и хранения личных данных пользователей).

## Метрики

### Бизнес метрики
- Количество ошибок первого рода в верификации (в %)
- Количество ошибок второго рода в верификации (в %)
- f1-score

### Технические метрики
- Latency (в мс)
- Использование памяти/CPU — в пределах SLA
- RMSE пикселей для изображения 100x100 пикселей

# План экспериментов

## Исследование данных
- Размеры изображений
- Кластеризация и поиск выбросов
- Нормализация

## Подбор эффективной архитектуры
Подход: Свёрточные нейросети с регрессией ключевых точек. Два распространённых варианта:

### Выбор таргета и лосс-функции
- Direct: модель предсказывает координаты напрямую. Более лёгкая и быстрая, но ниже точность в сложных условиях. В такой постановке лосс-функциями могут быть RMSE, WingLoss, MAE
- Heatmap-based: модель предсказывает N тепловых карт (по одной на точку). Координаты извлекаются как argmax / soft-argmax. Лучше точность, устойчивость к шуму. В такой постановке лосс-функцией будет покоординатное RMSE с целевой тепловой картой.

Фреймворком для написания модели был выбран PyTorch.

### Подбор гиперпараметров модели
- Количество слоев
- Архитектура блока
- Функции активации

### Подбор гиперпараметров обучения
- Тип и параметры оптимизатора
- Тип и параметры шедулера
- Количество эпох
- Клиппинг градиентов

# Запуск пайплайна
- Склонируйте репозиторий локально
```
git clone git@github.com:revit3d/ml-ops.git
cd ml-ops
```
- Загрузите и распакуйте данные для обучения, укажите путь до папки с изображениями и до разметки в конфигурационном файле `configs/training.yaml`. Для тестирования пайплайна обучения, установите флаг `fast_train=True`, для обучения модели установите флаг `fast_train=False`.
- Установите необходимые пакеты
```
python -m pip install --upgrade pip
pip install -r requirements.txt
pip install -e .
```
- Создайте папку, куда будет сохранена итоговая модель, и укажите путь до этой папки в конфигурационном файле
- Запуск обучения модели: `python -m src.train --config path_to_config [--verbose]`

## Отслеживание экспериментов

Проект использует **MLflow** для трекинга экспериментов.

### Локальный запуск
По умолчанию логи пишутся в папку `./mlruns`. Чтобы просмотреть результаты, запустите UI сервер:

```bash
mlflow ui
```

## Docker-контейнер для инференса

Приложение упаковано в Docker-контейнер для запуска офлайн-инференса без установки зависимостей Python.

### Сборка образа
Перед сборкой убедитесь, что модель обучена и находится в папке `saved_models/face_keypoint_detector`.

```bash
docker build -t ml-app:v1 .
```

### Запуск инференса через Docker-контейнер
Для получения предсказаний модели запустите команду

```bash
docker run --rm \
  -v $(pwd)/data/images:/data_in \  # Поменяйте на путь, где хранятся исходные данные (папка с файлами-изображениями)
  -v $(pwd):/data_out \  # Поменяйте на путь, в котором будет сохранен .csv-файл с предсказаниями
  ml-app:v1 \
  --input_path /data_in \
  --output_path /data_out/preds.csv
```

В результате в папке, примонтированной по пути `/data_out` (см. команду), будет сгенерирован файл `preds.csv`, в котором в каждой строке будет указано название входного файла и 14 предсказанных координат.

## TorchServe

Модель доступна как REST API сервис.

### Подготовка
Экспортируйте веса модели в формат `state_dict`:
```bash
python scripts/export_to_ts.py
```

### Запуск сервиса
```bash
docker build -t mymodel-serve:v1 -f Dockerfile.serve .
docker run -d -p 8080:8080 mymodel-serve:v1
```

### API
Endpoint: POST http://localhost:8080/predictions/face_kpts
Пример запроса:
```bash
curl -X POST http://localhost:8080/predictions/face_kpts -T path/to/image.jpg
```

Формат ответа:
```json
{
    "keypoints": [x1, y1, x2, y2, ..., x14, y14]
}
```
